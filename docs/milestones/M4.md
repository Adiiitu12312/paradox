# M4: setup, automatic capture and commit handling (complete with timing exception)

The owner accepted the M4 boundary exception on October 15, 2026: close M4 while
retaining the strict macOS 5 ms CI gate, unchanged baselines and visible failures.
This is milestone acceptance only; it does not declare the failed timing gate
passed or grant an exception to later milestones. M4.5 is next and is not included.

M1–M3 remain closed. M4 adds idempotent init/uninstall, asynchronous VS Code and
Cursor Run-on-Save configuration, a Claude PostToolUse adapter, print-only agent
rules and editor snippets, chained Git hooks, automatic staging, staged-content
marker stripping and rolling commit retention. Nothing auto-starts a process.

Commit stripping runs after Git prepares the actual commit index, including its
temporary index for file-specific commits. It streams staged blobs, removes only
the permitted first/second marker line, preserves every remaining byte and mode,
and replaces the index atomically under Git's lock convention. Working files are
never rewritten. Failure to strip aborts the commit to prevent marker leakage;
loop capture failures remain nonfatal and logged.

`paradox commit --no-verify` skips user pre-commit/commit-msg hooks while still
performing Paradox's stripping. Native `git commit --no-verify` has Git's normal
behavior and bypasses installed pre-commit hooks. Other Git operations remain
pass-through. Temporary commit hook directories are removed on return.

Existing hooks run before Paradox. Installation records its additions; uninstall
restores original hooks and removes only matching owned editor/AI entries. JSONC
comments, trailing commas and unrelated settings are preserved. Edited managed
hooks are retained with a message instead of being overwritten during uninstall.
Shared hooks track their initialized worktree owners and restore originals only
after the last owner uninstalls. Non-executable originals remain ignored and
existing executable symlink hooks retain their native behavior. Setup ownership
records use the same storage-cap accounting as other sidecar metadata; refusal
before the first record leaves original hooks/settings untouched.

The M7 core amendment supersedes M4's original retention rule: protection is now
per file, with its last three file-touching commits, uncommitted work, time and
minimum-count windows, and pins. Unrelated repository commits never age it out.
Size-cap eviction also protects each file's newest loop. See the
[amendment specification](../amendments-core.md). Purge reference deletion is
transactional; orphaned blobs after a crash are recoverable by `paradox loop --gc`.

Hosted functional validation passed W2/W3/W8,
all marker forms, exact staged/working byte separation, executable mode, partial
commits and unrelated staging, hook ordering/core.hooksPath/uninstall, JSONC and
idempotence, print-only behavior, configured editor/AI saves, retention boundaries,
pins and dirty paths, injected purge deaths, existing concurrency/crash tests,
terminal parity and audit. All capture gates and Linux/Windows pass-through gates
passed. macOS pass-through has the explicitly accepted boundary exception above.

All test repositories are disposable OS-temp repositories outside this project.
No local compiler is installed and local Node is unchanged. Watch remains M4.5;
init never starts it.

Recognized sh/bash/dash originals renamed during installation retain their
original `$0`, so Husky-style basename and relative helper lookup work. Their
body is read at invocation and passed to the shell with `-c`; original bytes,
arguments, stdin and exit status are preserved. Shell source diagnostics and
variables such as `BASH_SOURCE` may differ; unusually large shell hooks may hit
OS argument limits. Other interpreters/native hooks retain direct delegation.

Known limits: staged paths must be UTF-8. Candidate marker/shebang header lines
longer than 64 KiB are refused safely during stripping; normal file bodies stream
without loading the whole blob. Printed Neovim/JetBrains/Sublime snippets require
manual editor configuration; only VS Code/Cursor and Claude settings are merged
by init. No real editor UI was automated: integration tests execute the generated
save command and hook payloads directly in disposable repositories.
