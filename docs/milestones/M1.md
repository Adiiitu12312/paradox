# M1: implemented; Windows latency acceptance remains open

The public MIT-licensed repository is
[Adiiitu12312/paradox](https://github.com/Adiiitu12312/paradox).
All project commits use aditya raj's Git identity and are associated with
Adiiitu12312. Builds run on GitHub. Local toolchain installation was canceled
and Rust was removed. System Node remains v26.4.0; local Git is 2.54.0.windows.1.

## Built

Three-crate Cargo workspace, a single `paradox` CLI, global Git option routing,
original-argument pass-through, Unix process replacement, Windows inherited
console handling, the pure-Git escape command and development help. Reserved
later-milestone commands fail without modifying files. Commit/init conveniences
arrive in M4; use `paradox git` meanwhile. Do not alias Git to this build yet.

## Verification

[Hosted run for source revision 56d88ba](https://github.com/Adiiitu12312/paradox/actions/runs/38679474967)
completed on October 15, 2026. Functional checks passed on all three platforms:

- Formatting and clippy with warnings treated as errors.
- Dispatcher table, generated argument-preservation checks and Git collision guard.
- 50+ exact-output/error argument combinations and paired temporary repositories
  for branches, rebase, cherry-pick, revert, stash, restore and Git GC.
- Git stdin, Unicode/quoting, missing Git, worktrees and submodules.
- Real terminal detection/colors, pager, interactive rebase editor and Ctrl+C.
  Interrupt checks prove prompt exit and match Git's actual status, including the
  zero status returned by the tested Git for Windows shell alias.
- Dependency audit completed successfully.

There are seven grouped integration tests per OS, two dispatcher tests on Windows
and three on Unix, four terminal scenarios, and a separate release performance
gate. Every Paradox test invocation uses a temporary repository outside this
project. Blame parity uses committed content because Git supplies wall-clock
timestamps for uncommitted lines, making sequential comparisons time-dependent.

Development binaries were uploaded after functional and terminal checks. The
Windows download is 254,231 bytes compressed and 530,432 bytes extracted. Artifacts
expire after seven days. Using the binary requires Git, with no local compiler.

## Performance: 101 alternating pairs after eight warmup pairs

The gate uses the median of signed paired elapsed-time differences. Negative
individual samples are retained until after computing the median. The threshold
has not been raised and there are no retries until a favorable sample appears.

| Machine | Added time, Git version | Added time, status | Under 5 ms? |
| --- | ---: | ---: | --- |
| GitHub Linux | 0.536 ms | 0.548 ms | Yes |
| GitHub macOS ARM64 | 2.341 ms | 2.742 ms | Yes |
| GitHub Windows | 5.312 ms | 5.366 ms | **No** |
| Local Windows, Node host harness | 15.376 ms | 10.588 ms | **No** |

The local test used only the downloaded binary and the existing Node installation.
It confirmed exact status, graph log, diff and `-C` behavior in a fresh temporary
repository. Example output:

```text
PASS status --short
 M file.txt
PASS log --graph --oneline
* 9030164 first
PASS diff
@@ -1 +1 @@
-first
+changed
```

An earlier Windows hosted run measured below 5 ms, but later failures show this
target is not reliably met. Release footprint was reduced with one codegen unit
and abort-on-panic; the Windows results above still fail. The overall hosted run
is therefore **red**, despite passing functional checks and the audit. Linux and
macOS jobs pass. Artifacts are development builds.

## Open decision

M1 is not fully accepted under the original requirements. Either accept a
documented Windows latency exception at this milestone, or keep M1 open for
further Windows startup profiling and optimization. Preserve Git invocation
semantics and the strict performance gate until a decision is made.

M2 (loop store and capture) has not begun. No loop storage, auto-staging, hooks,
editor configuration or UI has been installed in any user repository.
