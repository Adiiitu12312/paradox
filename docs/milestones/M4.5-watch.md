# M4.5: manually started watch sessions (after M4, before M5)

This replaces the earlier optional post-M9 watch proposal. It is required at
M4.5 and is not implemented during M2. Nothing starts a watcher automatically.

## When to use it

Editors and agents with save/edit hooks use those hooks. For tools with no
post-edit hook, the user or agent explicitly starts `paradox watch` at the start
of a work session. `init`, hooks, the UI and other commands must never start it.
Never install a service, launch agent, scheduled task or login item.

## Lifecycle and identity

- Foreground by default; Ctrl+C stops it. `--background` detaches for this session
  only (Windows detached process; Unix double-fork).
- `--stop` stops the session. `--status` prints running/not running, PID, uptime
  and loops created.
- Print one clear start line: `Paradox watching N tracked files; stops after 30 min idle`,
  adjusted for configured idle behavior. Print one clear exit line.
- One instance per repository, enforced by PID and a session lock in `.paradox`.
  This lock is distinct from short-lived capture write locking. Recover stale PID
  files after crashes and validate identity before stopping a PID.
- `watch_idle_minutes` defaults to 30; 0 disables idle exit. Idle means no change
  events. Errors are logged to `.paradox/log` and never crash or stop the session.

## Native events and capture

- Use `notify`: inotify, FSEvents or ReadDirectoryChangesW. No polling loops or
  periodic full scans.
- Watch only directories containing tracked files (`git ls-files` plus `track`
  paths), never the whole tree. Ignore `.git`, `.paradox`, node_modules, build
  output and gitignored paths.
- On Linux check the inotify watch limit before starting. If needed, use fewer
  or shallower directories; warn exactly which paths are not covered and how to
  raise the limit. Do not silently broaden to whole-tree watching.
- Watch the Git index and the Paradox track list. Refresh `git ls-files` only
  when these change so new additions become covered without restarting.
- Debounce each file for 300 ms. Temp-file + rename, delete + create and truncate
  + write all count as changes. Read only after the debounce window settles.
- Settled events call the same implementation as `paradox loop <file>` with
  kind `save`, including dedup, size/binary/secret skips and message parsing.
- Suppress Paradox's own rewind/commit-time writes using an in-process/file-based
  writing marker.
- If more than 50 tracked files change within two seconds, pause per-file loops.
  After the burst settles, record at most one deduped loop per changed file with
  kind `scan` and message `bulk change`. Log the bulk operation.
- Reuse the repository write lock and dedup across watcher, editor and agent
  capture commands. Identical content must not produce duplicate loops.

## Acceptance tests (Windows and macOS included in CI)

- Non-hooked saves (`sed -i`, scripts, temp-file-and-rename) create exactly one
  loop each, using a new message line when present.
- Untracked/ignored files, `.git`, `.paradox` and Paradox's own rewind writes
  create no loops.
- Simulated checkout touching 500 tracked files has no per-file storm and at
  most one `scan` loop per changed file.
- `paradox track` and `git add` additions become covered without restarting.
- Refuse a second instance; recover a stale PID file after forceful process death.
- Verify configured idle exit, `--stop`, and no remaining Paradox process after
  stop or idle exit.
- Watcher plus 20 parallel loop commands and editor bursts preserve integrity and
  dedup identical content.
- After ten minutes idle on 50,000 tracked files, record RSS and CPU. Fail above
  20 MB RSS and target near-zero CPU. On Windows record the result and establish
  a documented threshold if the OS makes 20 MB unrealistic.
- Verify per-file debouncing, tracked-set refresh, bulk handling and Linux limit
  warnings. No M4.5 completion report before every required check passes.
