# M4.5: watcher implementation and verification (in progress)

M4 is closed with its accepted hosted timing exception. M4.5 is required before
M5. The authoritative requirements remain in [M4.5-watch.md](M4.5-watch.md).

The implementation adds explicit foreground/background sessions and stop/status
commands. Native `notify` events feed a blocking channel; there is no polling
backend, periodic scan, service, scheduled task or automatic startup. Unix
background sessions double-fork; Windows uses a detached process. A repository
session lock establishes liveness, while a unique session token authenticates
the stop mailbox without sending signals to a potentially reused PID.

Only nonrecursive directories containing eligible tracked files are watched.
Separate metadata watches cover the Git index and explicit track list. Coverage
refreshes on their native events; newly covered paths enter settled capture so
an immediate save in a new directory cannot fall between tracking and native
watch registration. Startup does not capture the whole repository. Ignored
paths, node_modules and build/sidecar/Git data are excluded, including ignored
paths that were force-added or explicitly tracked.

Per-file changes settle for at least 300 ms. Ordinary capture also waits through
a two-second classification window so a bulk operation can be recognized before
emitting per-file save loops. This deliberately adds up to two seconds of initial
capture latency. Settled files have independent deadlines, so another file's
continuous edits cannot starve them. More than 50 distinct paths in a rolling
two-second window activates bulk handling; after quiet, shared capture records
deduped `scan` loops with message `bulk change`. Ordinary events use `save` and
the existing parser, skips, locks and dedup. Existing rewind writing markers and
the stat cache suppress Paradox's own restored bytes.

An idle session holds no LoopStore or database connection. Short-lived store
opens perform capture and persist counters. Idle exit defaults to 30 minutes;
`watch_idle_minutes = 0` disables it. Stop is requested through the authenticated
metadata mailbox. Foreground exits print a notice; background notices are kept
in `.paradox/watch-output.log`. Linux checks its inotify limit and reports exact
uncovered directories with instructions to raise `fs.inotify.max_user_watches`.

The performance gate now uses 201 interleaved samples per executable after 16
warm-up runs each, in each of three consecutive rounds in one process. Signed
paired differences remain signed until the median. A command fails only after
two rounds exceed its existing ceiling. Limits remain 5 ms on Linux/macOS and
20 ms on Windows, with the existing stored-baseline guard unchanged. There are
no automatic baseline increases or selective CI retries.

## Evidence so far

- [Preparation 38711561567](https://github.com/Adiiitu12312/paradox/actions/runs/38711561567)
  compiled and passed clippy, then caught missing dispatcher ownership for
  `watch`. It was fixed before behavioral acceptance.
- [Preparation 38712014248](https://github.com/Adiiitu12312/paradox/actions/runs/38712014248)
  passed all watcher tests except the concurrency fixture's count assertion.
  The fixture used truncate/write while explicit captures ran, exposing temporary
  content. It now uses atomic editor-style saves and retains a strict one-loop
  assertion plus database integrity and blob-reference checks.
- [Preparation 38712809549](https://github.com/Adiiitu12312/paradox/actions/runs/38712809549)
  passed Linux clippy and the full functional suite, including watcher saves,
  rename/sed saves, exclusions, bulk capture, independent deadlines, slow changes
  outside the bulk window, tracking refresh, rewind suppression, concurrency,
  singleton/stale recovery, stop/idle exit, background and Ctrl+C cleanup.
- [Preparation 38713356913](https://github.com/Adiiitu12312/paradox/actions/runs/38713356913)
  passed the immediate-after-track registration correction.
- [Full matrix 38713749424](https://github.com/Adiiitu12312/paradox/actions/runs/38713749424),
  source `8091919`, passed every Linux/macOS functional, terminal and performance
  check, and audit. Linux version/status round medians were 0.880/0.930/0.990 ms
  and 0.953/0.910/0.940 ms. macOS measured 4.010/3.786/4.218 ms and
  4.386/4.005/4.010 ms: all rounds passed unchanged ceilings. Capture save/scan
  was 5.590/188.521 ms on Linux and 11.451/173.146 ms on macOS.
  Windows passed all watcher tests except the background launcher test, which
  hung waiting for output-pipe EOF. The run was cancelled to inspect its partial
  log; footprint jobs were consequently skipped, not passed.
- Source `3048e12` adds a Windows-only guard that temporarily clears inheritance
  on the launcher's original standard handles while spawning the detached child,
  then restores it. Explicit null/log stdio still reaches the child. The bounded
  regression test also guarantees cleanup before reporting a timeout.

Cross-platform acceptance and the real ten-minute idle RSS/CPU gate are pending.
The footprint test uses a production release build without fault injection,
50,000 tracked files, and OS-native RSS/CPU measurements. It always stops the
watcher before asserting under 20,000,000 bytes RSS and under 0.1% idle CPU.
No M4.5 completion claim is made before every required check passes.

All executable tests use disposable OS-temp repositories outside this project.
No local Rust/C++ tools were installed or Node version changed. Local unsigned
binary execution remains subject to the owner's Windows Application Control.
