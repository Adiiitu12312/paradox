The implementation adds explicit foreground/background sessions and stop/status
commands. Native `notify` events feed a blocking channel; there is no polling
backend, periodic scan, service, scheduled task or automatic startup. Unix
background sessions double-fork; Windows uses a detached process. A repository
session lock establishes liveness, while a unique session token authenticates
the stop mailbox without sending signals to a potentially reused PID.

Only nonrecursive directories containing eligible tracked files are watched.
Separate metadata watches cover the Git index and explicit track list. Coverage
refreshes on their native events; newly covered paths enter settled capture so
an immediate save in a new directory cannot fall between tracking and native
watch registration. Startup does not capture the whole repository. Ignored
paths, node_modules and build/sidecar/Git data are excluded, including ignored
paths that were force-added or explicitly tracked.

Per-file changes settle for 300 ms, with independent deadlines so another file's
continuous edits cannot starve them. Native callback timestamps define the rolling
two-second bulk window even when capture I/O delays processing queued events.
More than 50 distinct paths activates bulk handling. Already captured rows owned
by this watcher within that window become `scan` loops with message `bulk change`;
after quiet, shared capture records the latest bytes and coalesces only unpinned,
watcher-owned versions to at most one scan per changed path. Pinned history and
rows created by other agents are preserved. Ordinary events use `save` and
the existing parser, skips, locks and dedup. Existing rewind writing markers and
the stat cache suppress Paradox's own restored bytes.

An idle session holds no LoopStore or database connection. Short-lived store
opens perform capture and persist counters. Idle exit defaults to 30 minutes;
`watch_idle_minutes = 0` disables it. Stop is requested through the authenticated
metadata mailbox. Foreground exits print a notice; background notices are kept
in `.paradox/watch-output.log`. Linux checks its inotify limit and reports exact
uncovered directories with instructions to raise `fs.inotify.max_user_watches`.

The performance gate uses 201 interleaved samples per executable after 16
warm-up runs each, within one process per assessment. CI schedules three
consecutive fresh-host assessments of the same precompiled release binary and
Rust harness. Signed paired differences remain signed until the median. A
command fails after two assessments exceed its existing ceiling; missing or
invalid reports fail. All raw pairs, source and binary hashes are retained.
Direct local tests retain three rounds in one process. Limits remain 5 ms on
Linux/macOS and 20 ms on Windows, with the stored-baseline guard unchanged.
Capture gates remain strict single assessments. There are no automatic baseline
increases or selective CI retries.
