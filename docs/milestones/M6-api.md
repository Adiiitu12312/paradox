# M6 backend and frontend contract

All paths in JSON are exact UTF-8 repository-root-relative Git paths. Display them as text; control characters are JSON escaped. Errors use `{ "error": "message", "code": "invalid_request|stale_diff|git_failed|unauthorized|forbidden|not_found", "commands": [] }` with HTTP 400/409/422/401/403/404 respectively. Successful API responses include `commands: [{ "argv": ["git", "..."], "exit_code": 0, "stderr": "" }]` for the collapsible command log. No endpoint accepts arbitrary Git arguments or client-generated patch text.

## Session and assets

The CLI calls `paradox_ui::serve(repo, UiOptions { assets_dir: Option<PathBuf> }, on_ready).await`. The synchronous callback receives `UiReady { address: SocketAddr, url: String }`; `url` is the complete bootstrap URL. Binding is always `127.0.0.1:0`. The CLI owns printing/opening that URL and constructs its Tokio runtime only for `ui`.

The bootstrap URL is `http://127.0.0.1:PORT/?token=SESSION_TOKEN`. A valid bootstrap request sets `paradox_session=TOKEN; Path=/; HttpOnly; SameSite=Strict` and redirects (303) to `/`. All subsequent assets, API requests and WebSocket connections require that cookie. The frontend uses same-origin `fetch`; it needs no token in JavaScript. Exact Host and any supplied Origin must match the bound address; mutations and WebSocket upgrades require the exact Origin. There is no CORS exception.

Each tab opens `ws://${location.host}/api/session` and retains that socket. Closing the last session socket exits the server after a two-second reload grace. The first tab has 60 seconds to connect. Ctrl+C also exits. No command starts a watcher automatically.

The parent-owned `assets` module exports `pub(crate) fn get(path: &str, assets_dir: &Option<PathBuf>) -> anyhow::Result<Option<Asset>>`, where `Asset { pub bytes: Vec<u8>, pub content_type: String }`. The path is the HTTP path (including leading `/`); `/` selects `index.html`. Production bytes are embedded; an explicitly supplied local assets directory serves a Node build through the same authenticated origin.

## Read endpoints

- `GET /api/status`: `{ repo: { root, name, branch: string|null, head: string|null, unborn: boolean }, files: [{ path, old_path: string|null, index_status: string, worktree_status: string, untracked: boolean }], commands }`. Untracked directories use Git's normal collapsed-folder representation. Status characters are the native porcelain characters (`.` for unchanged, `?` for untracked).
- `GET /api/graph?cursor=0`: `{ commits: [{ sha, parents: string[], subject, author_name, author_email, time: number, refs: string[] }], next_cursor: string|null, head: string|null, commands }`. `time` is Unix seconds; refs are full native ref names. Pages contain at most 200 commits. Cursor is an opaque string to the frontend; pass it back unchanged. Refresh starts again without a cursor.
- `GET /api/commit/:sha`: `{ sha, parents, subject, message, author_name, author_email, time, files: [{ path, old_path: string|null, status, additions: number|null, deletions: number|null }], commands }`.
- `GET /api/diff?path=...&view=working|staged[&commit=SHA]`: `{ path, view, commit: string|null, token, old_text, new_text, old_present, new_present, binary, truncated, hunks: [{ id, header, lines: [{ id, kind: "context"|"addition"|"deletion", text, old_line: number|null, new_line: number|null }] }], commands }`. Working view compares index to working bytes; staged view compares HEAD to index. A supplied commit selects its first-parent diff and disables staging controls. A symlink displays its link-target text, never the linked external file. Binary/oversized data has empty texts and no selectable hunks; `binary`/`truncated` explains why. Text reads and patches are bounded to 8 MiB.

## Mutation endpoints

`POST /api/stage` and `POST /api/unstage` accept one of:

```json
{ "mode": "files", "paths": ["src/a.ts"] }
{ "mode": "all" }
{ "mode": "hunks", "path": "src/a.ts", "token": "FROM_DIFF", "hunk_ids": ["h0"] }
{ "mode": "lines", "path": "src/a.ts", "token": "FROM_DIFF", "line_ids": ["h0:l2"] }
```

Staging selections require a working-view diff token; unstaging selections require a staged-view token. Tokens and IDs are generated by the server. The backend recomputes the diff/fingerprint and returns 409 `stale_diff` on any mismatch; the frontend then refreshes instead of guessing. Selected patches come exclusively from the current server-generated native diff. Whole-file and all modes support new files and unborn repositories. Success: `{ changed: true, commands }`.

`POST /api/commit`: `{ "message": "literal commit message", "amend": false }`. Success: `{ head: "NEW_SHA", commands }`. This commits the existing index only, preserving partial staging and unrelated unstaged edits. It uses the same shared mandatory marker-strip, user-hook and purge orchestration as the CLI. Working files retain marker bytes. Failed user hooks return 422 and their output in the command log.

JSON request bodies are bounded to 2 MiB. Calls that run Git or touch repository files execute in blocking workers; neither the HTTP event loop nor browser-wait/session handling owns a `LoopStore` lock.

The graph uses Git's default commit ordering and preserves native parent IDs and refs. Explicit date/topological ordering eagerly traverses the full DAG before returning a bounded page: an isolated native-Git probe on 100,000 commits measured 322.2 ms with `--date-order`, 323.2 ms with `--topo-order`, and 38.7 ms with the default order. Functional pagination runs in the debug suite; the unchanged under-300-ms first-page gate runs separately against release code.
